# 第三階段：使用者體驗優化 (UX Polish) ✓ 已完成

目標：提升視覺質感與操作便利性。

## 1. 圖示擷取 (Icon Extraction)

- [x] 從 .exe 檔案中動態讀取圖示 (Icon)。
- [x] 圖示必須使用磁碟快取，避免每次開啟 app 都需要從檔案中重新讀取圖示
- [x] 取不到圖示時（URL 項目、或 exe 路徑失效）顯示 Segoe MDL2 fallback 字符，另可由使用者指定自訂圖示（第七階段）。
- [x] 同一項目同時被要求載入時共用同一次擷取（`IconService` 以快取路徑為鍵保存進行中的工作）：新增時的即時載入與容器實體化的載入本來就會同時發生，冷快取下兩者都去擷取，寫檔輸的一方吃到共用違規並靜默回傳 null，剛拖入的項目因此約有一半機率沒有圖示。
- [x] 快取寫入採「先寫 `.tmp` 再更名」：`File.Exists(快取路徑)` 就是「是否已快取」的判斷，就地寫入會先建檔再填內容，中間那段空窗期該判斷會通過而讀到截斷的 PNG。
- [x] 圖示的釋放分兩層，不可混用：離開畫面只釋放記憶體中的 bitmap（容器回收與 `ReleaseHiddenIcons`）；**刪除**則必須連磁碟快取一併清除，因為快取以 `AppItem.Id` 為鍵，項目一旦離開 workspace JSON 就沒有任何地方還記得那個 id。刪除項目、刪除資料夾（連同其中項目）、刪除 workspace（先讀出 id 再刪檔）三處皆已涵蓋。
  - 匯入與「複製目前 workspace」會保留項目 id，故兩個 workspace 可能共用快取；刪除其一會順帶清掉另一邊的快取，代價僅是下次重新擷取，不值得為此做跨 workspace 的引用計數。

## 2. 拖放支援 (Drag & Drop)

- [x] 允許使用者將桌面上的 .exe 或 .lnk (捷徑) 直接拖入視窗。第七階段起一併接受網址與 `.url` 網際網路捷徑檔。
- [x] 自動解析路徑並直接加入目前選取的資料夾（或「未分類」），不開啟對話框。
- [x] 落點即插入位置：新項目插在拖放時 GridView 指示線所在之處，而非一律附加在最後；一次拖入多個檔案時整批依序落在同一處。落在最後一格之後、空狀態面板上、或容器尚未實體化時才附加至末端——那也正是指示線在該處的表現。
  - 插入索引以走訪已實體化容器的幾何位置決定，不用命中測試：拖曳事件的 `OriginalSource` 是清單本身（同側邊欄的 `TryResolveRailDropTarget`），而 GridView 會為了讓出插入間隙而分開磁磚，使用者最可能放手的那一點反而沒有任何容器。
